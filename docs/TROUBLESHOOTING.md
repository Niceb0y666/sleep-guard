# 故障排查

先查看菜单栏状态、最近检测时间和“状态与设置…”中的错误文字。休眠哨兵监测的是 `SleepDisabled` 设置；通知授权、通知提交和实际睡眠行为应分别检查。

## 菜单栏没有图标

从 Finder 打开 `.app`，等待应用启动。它是菜单栏工具，不要求 Dock 中出现图标。如果菜单栏空间有限，检查是否有菜单栏管理工具折叠了该图标。

关闭状态窗口不会退出应用；选择“退出休眠哨兵”才停止运行。已运行时再次双击应用应打开状态窗口。使用相同 bundle identifier 的第二个实例会退出，因此避免同时运行不同目录中的多个副本。

如果应用启动后立即退出，尝试在终端进行单次诊断：

```bash
./dist/休眠哨兵.app/Contents/MacOS/SleepGuard --diagnose
```

该路径适用于仓库默认构建目录；安装在其他位置时，改为对应 `.app` 内的可执行文件路径。诊断模式不创建菜单栏，并会在输出后退出，这是预期行为。

## 显示“休眠状态未知”

“未知”表示应用未取得可信的目标开关值，不表示开关已经关闭。点击“马上检测”，并独立运行：

```bash
pmset -g
```

| 原因提示 | 含义与处理 |
| --- | --- |
| 无法运行 `pmset` | 系统命令启动失败；保留错误说明，检查系统工具是否可用 |
| 读取电源设置超时 | 本次查询超过 3 秒；应用不会阻塞主界面，可稍后重新检测 |
| `pmset` 执行失败 | 命令未正常成功退出；在终端独立读取，检查是否也出现错误 |
| 输出无法解码 | 输出不是预期 UTF-8 文本；保留系统版本和最小必要错误信息 |
| 未返回 `SleepDisabled` | 当前输出缺少目标字段；应用按未知处理，不猜测默认值 |
| 值无法识别或冲突 | 目标值不符合解析契约；检查确切目标行，提交脱敏后的最小复现 |

正常监测不需要 `sudo`。不要为读取错误先执行修改电源设置的命令。若需要报 issue，请提供应用版本、macOS 版本、架构、错误文字，以及必要的目标字段片段；不要直接公开包含其他应用活动的完整诊断输出。

## 最近检测时间没有更新

应用退出后不会检查；电脑处于睡眠时，定时器也不会按固定间隔运行。唤醒后应立即重查，或通过菜单中的“马上检测”发起读取。

目标间隔为 10 秒，允许系统调度延迟。若醒来后较长时间仍不更新，确认应用仍在运行，手动刷新，再重启应用检查。

## 看到橙色提示，但没有通知

按以下顺序检查：

1. “休眠禁用时通知我”是否勾选；暂停自动提醒不会隐藏橙色菜单栏状态。
2. 权限是否显示“系统通知已获授权”；尚未授权时点击“启用通知”，拒绝过权限时进入“通知设置…”。
3. 是否选择“只在首次发现时”，或上一次成功提交后尚未到重复间隔。
4. 状态窗口是否显示“通知提交失败”；失败后约 60 秒重试，不是立即每轮重发。
5. 在系统设置中检查该应用的通知样式、声音，以及专注模式。

点击“测试提醒”进行手动检查。首次测试会先请求授权；拒绝权限后不会发送测试通知。暂停自动提醒时，手动测试仍可使用。

系统接收请求后仍可能不显示横幅。“系统通知已获授权”只说明权限，“没有提交错误”只说明请求未返回错误；是否看到横幅应由实际观察确认。临时静默授权可能只投递到通知中心。

如果应用更新或重建后通知行为改变，重新检查系统通知设置，并使用最终 `.app` 进行测试。本地 ad-hoc 签名的通知权限行为应在实际使用环境确认，不能以旧构建的成功结果代替。

## 显示“系统允许休眠”，电脑合盖仍在运行

此状态只表示明确读到了 `SleepDisabled = 0`。实际睡眠还可能受外接设备、应用活动及其他系统条件影响，应用没有读取这些条件，不能据此确定原因。

请独立复核 `pmset -g` 的目标字段；若与应用一致，问题已超出这个开关的监测范围，应继续进行 macOS 的睡眠与唤醒排查。休眠哨兵不会确认电脑真实睡着，也不会据此归因任何第三方工具。

## 设置又变回“休眠禁用”

应用只报告读数变化，不知道是谁修改了开关。状态记录显示的是检测时间，也不能证明修改动作发生在该秒。

如果你选择恢复开关，可使用“恢复休眠说明…”中的命令，在终端自行执行并再次检测。不要把再次发现禁用当作某款软件的责任证据。

## 登录时没有启动

确认应用仍在启用时的安装位置，建议放在“应用程序”文件夹。打开应用，检查“登录时启动”和系统设置 → 通用 → 登录项。

- 待批准：按系统提示完成批准。
- 未启用：由你决定是否勾选并注册。
- 显示已启用：系统报告该登录项已登记，但仍需实际下一次登录后观察菜单栏是否出现。
- 注册报错：查看具体错误；路径无效、应用移动或系统批准问题应分别处理。

更换应用位置后，应重新检查登录项。待批准项需要取消时，可在系统设置中管理。不要仅凭 `enabled` 状态宣称已经完成实际重登测试。

## 系统拦截下载的应用

当前构建使用本地 ad-hoc 签名，并未以 Developer ID 证书完成公开分发签名或 Apple 公证。来自网络的应用可能触发系统安全检查。

先确认下载来源和文件完整性。若你确认信任此产物，可以按照系统设置 → 隐私与安全性中的提示处理；没有相关提示或出现“已损坏”时，重新下载或从源码构建，并检查签名：

```bash
codesign --verify --deep --strict ./dist/休眠哨兵.app
```

校验通过只说明 bundle 签名完整，不代表已公证。不要关闭 Gatekeeper 或系统整体安全功能来解决单个应用的问题。

## 架构或系统版本不匹配

最低系统版本是 macOS 13。构建脚本按当前 Mac 的 `uname -m` 生成对应架构产物，不会一次生成同时包含所有架构的 universal app。

当前已记录验收范围见[验证记录](VALIDATION.md)。在不同架构的 Mac 上，优先按[项目说明](../README.md)从源码构建，再进行必要运行验证。

## 提交问题

在仓库 issue 中说明：应用版本、macOS 版本、处理器架构、操作步骤、预期结果、实际结果和最小错误片段。通知问题请分别描述权限、请求是否报错、是否实际出现横幅；启动问题请区分登录项登记状态与实际登录启动结果。

避免上传个人路径、账户信息、其他应用活动记录和密码。应用不会要求在自身窗口输入管理员密码。
