### 窗口构建异常修复复核

初次实际启动新版窗口时，后续控件不可见。原因是分隔线在加入栈之前就激活了与另一文本视图的宽度约束，两视图尚无共同祖先，触发约束异常并中断构建；此前静态复核未发现该问题。

修复后，分隔线在创建时仅约束自身高度为 1 点，跨视图宽度约束移到全部控件已加入栈之后激活。该修复已静态复核，后续本机检查确认通知、登录与历史等后部控件全部可见。此证据确认本次构建中断已修复，不证明长错误注入或不同屏幕条件已经验收。

## 解析器案例

v1.0.0 GitHub 源码发布前，从完整的发布源码目录复制到独立检查目录，实际执行 `bash test.sh` 与 `bash package.sh`。13 个解析案例再次通过；应用重新构建、归档，解压后的签名校验通过。该检查没有修改系统休眠设置，也不证明 v1.1.0 的管理员恢复流程。

[PowerMonitorTests.swift](../PowerMonitorTests.swift) 包含六个明确结果和七个未知结果案例。

明确结果覆盖：空白分隔的 `0` / `1`、`=` 分隔的 `false`、`:` 分隔的大写 `TRUE`、相同含义的允许值重复，以及相同含义的禁用值重复。

未知结果覆盖：空输出、目标字段缺失、不支持的值 `2`、只有字段没有值、值后含额外文本、相似名称 `SleepDisabledFuture`，以及互相冲突的重复值。

这些测试只调用解析器，不修改系统电源设置，也不验证通知权限或实际合盖行为。测试运行方法见[项目说明](../README.md)。

## 既有监测与提醒代码审查检查点

- 监测命令固定为 `/usr/bin/pmset -g`，不接受用户命令参数；监测路径不执行特权恢复。
- 读取和等待在后台，查询管理与 3 秒超时使用独立队列；重复请求合并。
- 缺失、未知及冲突数据不会显示为允许休眠。
- 初次读数已是禁用时，也进入提醒判断。
- 只有通知提交成功后才记录自动提醒时间；失败采用 60 秒独立重试节流。
- 正在提交的提醒有防重标志；完成回调核对禁用事件标识。
- 首次测试请求保存测试意图，授权明确后继续发送，不在授权仍未决定时提前清空。
- 允许、禁用和未知分别呈现；未知时停止根据旧值发起新提醒。
- 登录项依据 `SMAppService` 实际报告状态呈现。

| 实际 `0 → 1 → 0` 变化 | 在用户明确选择进行受控系统设置测试后，对比读数、状态变化时间和恢复后通知清理 |
| 提醒间隔与失败重试 | 使用可控通知接口或独立测试环境验证重复间隔、单次模式与提交失败，不必修改日常机器设置 |

| 最低及其他 macOS 版本 | 在实际目标系统上运行；部署目标为 macOS 13 不能证明已在 macOS 13 实机验收 |
| 完整窗口边界 | 检查禁用状态、五条历史、较长错误信息、不同显示缩放与深浅色模式 |

## 复核命令

在仓库根目录可复核解析器、重新构建，并执行只读诊断：

```bash
bash test.sh
bash build.sh
./dist/休眠哨兵.app/Contents/MacOS/SleepGuard --diagnose
pmset -g
```

对比 `status` 和 `SleepDisabled` 对应含义，不将检测完成时间误读为开关修改时间。

检查 bundle 结构与签名完整性：

```bash
plutil -lint ./dist/休眠哨兵.app/Contents/Info.plist
codesign --verify --deep --strict ./dist/休眠哨兵.app
```

这些命令不会证明公证、通知呈现或登录后自动启动。新的发布产物应重新执行相关检查，不应仅引用旧构建的成功结果。

发布 ZIP 可通过以下命令重新打包：

```bash
bash package.sh
```

[打包脚本](../package.sh)在临时目录构建，生成 `dist/休眠哨兵.zip`，再解压并检查应用签名。该检查证明此次归档与解压没有破坏 bundle 签名，不证明其他 Mac 的首次打开体验。
